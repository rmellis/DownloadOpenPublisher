Microsoft Agent (Clippy) Assistant Integration Update (Remote MKLab Architecture)

1. Legal & Hosting Architecture Disclosure:
   - ZERO LOCAL BUNDLING: Absolutely no Clippy proprietary assets, character models, sprite atlas sheets (map.png), timing metadata (agent.js), or audio sound effect files (sounds-mp3.js) are stored, bundled, or packaged inside the OpenPublisher application repository or local installation.
   - ZERO SERVER HOSTING ON OPENPUBLISHER.APP: The openpublisher.app website and hosting infrastructure do not host, store, or distribute any Clippy or Microsoft Agent proprietary content.
   - DIRECT RUNTIME FETCH: When the user summons Clippy via the ribbon button, the desktop wrapper initiates a direct runtime client-side fetch from the open-source community project hosted by MKLab (https://mklab.eu.org/clippy/) based on the Smore Clippy.js project (Cinnamon Software / Double Agent unpacker).
   - ON-DEMAND LAZY LOADING: No assets, stylesheets, or scripts are downloaded until the user explicitly clicks the "Clippy" button.

   - Location: File tab -> Help section (#about-btn-group).
   - Position: Placed as the first item in the Help group, immediately to the left of "Knowledge Base" ([Clippy] [Knowledge Base] [About]).
   - Design: OpenPublisher standard .tool-btn styling, featuring an authentic vector paperclip icon with animated eyes, label "Clippy", and tooltip "Summon Microsoft Agent Assistant (Clippy)".

3. Offline & Unreachable Host Fallback Modal Dialog:
   - 7-Second Watchdog: If the user is offline, DNS resolution fails, or the remote MKLab server cannot be reached, the loader aborts cleanly without throwing uncaught JavaScript errors or breaking the application.
   - Flow UI Modal Window: A custom modal dialog (#custom-clippy-error-modal) appears over the workspace:
     - Header: "Clippy Unavailable" with alert icon.
     - Body: Explains that the remote host (mklab.eu.org) could not be reached, re-iterating that no proprietary assets are stored locally or on openpublisher.app, and advising the user to check their internet connection.

   - Clean Dismissal (Elimination of Frozen Clippy Image):
     - Root Cause: Calling _clippyAgent.play('GoodBye', callback) treated the callback function as the timeout parameter, causing an immediate exit branch and leaving the callback unexecuted. As a result, _clippyAgent.hide() was never called, leaving the draggable paperclip frame frozen on screen while interactions were disabled.

       - hideClippyAssistant() plays the native Hide animation via _clippyAgent.hide(false), immediately dismisses speech balloons, sets display: none on all .clippy DOM nodes upon animation completion, and arms a 1200ms safety timer.
       - showClippyAssistant() unhides the DOM nodes with display: block, invokes _clippyAgent.show(true), and triggers the Greeting animation, ensuring seamless toggling without ghosting.

10. Queue Deadlock Resolution, Double Size Scaling & Drag Preservation:
   - Queue Deadlock & Toggle Crash Fix:
     - Identified root cause in clippy.js: clippy.Queue.prototype.clear() emptied this._queue array but left this._active = true. When toggling off mid-action, _active became permanently stuck at true, causing _progressQueue() to never advance on subsequent play(), speak(), or moveTo() calls. This produced a motionless still image on re-enable.
     - Patched clippy.Queue.prototype.clear to explicitly reset this._active = false.
     - Patched clippy.Agent.prototype.stop to clear queue, reset _queue._active = false, clear animations, and hide balloons.
     - Enhanced showClippyAssistant() and hideClippyAssistant() to force _queue._active = false and invoke _clippyAgent.resume(), guaranteeing seamless continuous toggle cycles.
   - Double Size & Regular Size Context Menu Controls:
     - Added "Regular Size" and "Double Size" options to Clippy's right-click context menu (#clippy-context-menu) with real-time teal checkmark indicators.
     - Implemented setClippySize(doubleSize) using CSS transform: scale(2) with transform-origin: bottom right to keep Clippy grounded inside the visible viewport.
     - Enhanced clippy.Balloon.prototype._position to use getBoundingClientRect() on target elements, ensuring speech balloons anchor precisely to the 2x scaled visual boundaries rather than overlapping the character.
   - Drag Balloon & Countdown Preservation:
     - Identified root cause: clippy.Agent.prototype._startDrag calls this._balloon.hide(true), which previously purged action buttons and the countdown bar from the DOM before dragging started.
     - Added isDragHide flag to clippy.Balloon.prototype.hide(immediate, isDragHide) so that action buttons and the 20-second countdown bar are preserved during moves.
     - On drag release (_finishDrag), the speech balloon re-anchors to Clippy's new coordinates with its action buttons and countdown timer intact and fully interactive.

11. Instant Tip Cycling, Dangling Timer & Hover Protection, Zero Drag Offset & CRT Blender Filter:
   - Next Tip Responsiveness & Instant Cycling:
     - Identified root cause: Clicking "Next Tip" previously called self.hide(true) and speakContextualTip(), which ran _clippyAgent.play('Explain') before speak(). In clippy.js, play() queued the entire 1.5-second Explain animation, leaving the speech bubble vanished for 1.5 seconds and making the button feel completely unresponsive.
     - Resolution: speakContextualTip() now triggers _clippyAgent.speak(chosenTip) immediately with zero queue delay, while running the Explain gesture concurrently on _animator. When clicking "Next Tip", the speech balloon stays open and transitions immediately into typing the new tip, resetting the 20-second countdown bar.
   - Message Box Auto-Dismissal Fix & Hover Protection:
     - Identified root cause: In clippy.js, this._hiding was never cancelled on hide(true) or speak(). If a new tip was displayed while a previous 20-second timer was still ticking down in the background, the old timer fired and killed the new balloon midway through reading it.
     - Resolution: Explicitly cleared this._hiding across speak(), hide(), _clearActions(), _sayWords(), and stop().
     - In addition, attached mouseenter and mouseleave listeners to .clippy-balloon: hovering pauses this._hiding and pauses the .clippy-timer-bar countdown animation; leaving resumes. The message box will never disappear while the user is reading or moving to click.
     - Background gaze tracking and idle animations are also guarded so they never interrupt active speech balloons.
   - Zero Drag Offset in Double Size:
     - Identified root cause: Using transform-origin: bottom right shifted the visual element by 124px horizontally and 93px vertically relative to CSS top/left.
     - Resolution: Switched transform-origin to top left !important. With top-left scaling, the visual top-left corner matches CSS top/left exactly. The grab point remains locked under the cursor throughout drags with mathematically zero offset (0px X, 0px Y).
     - Patched Agent.prototype.reposition to clamp against actual 248x186 scaled dimensions so Clippy stays cleanly within window boundaries.
   - CRT Style Blender Filter:
     - Embedded an SVG CRT Blender Filter (#clippy-crt-filter) that transforms raw 1997 pixelated dither dots into clear, smooth, retro-authentic imagery:
       - Bilinear dither blending (<feGaussianBlur stdDeviation="0.32">) smooths out blocky pixel noise.
       - Unsharp edge matrix (<feConvolveMatrix kernelMatrix="0 -0.35 0 -0.35 2.4 -0.35 0 -0.35 0">) keeps paperclip wire outlines, eyes, and eyebrows razor-sharp.
       - Subtle phosphor bloom (<feGaussianBlur stdDeviation="0.6">) delivers warm CRT glow without darkening the sprite.
       - Component transfer enhances vibrancy and contrast.
     - Automatically applied to .clippy.clippy-double-size as .clippy-crt-filter.
     - Added "CRT Filter" toggle item with real-time teal checkmark in the right-click context menu.

12. Animation Loop Elimination, 1.5x Intermediate Medium Size & 2px Teal Context Menu:
   - Root Cause & Elimination of Animation Loop & Frozen Balloons:
     - Root Cause 1: In Smore clippy.js, Balloon.prototype.hide(true) called jQuery this._balloon.hide(), but NEVER set this._hidden = true. Because this._hidden remained false, subsequent drag finishes or reposition calls invoked this._balloon.show() and restored the speech balloon to visibility. Furthermore, because _clearActions() had already detached the buttons and timer bar, the balloon reappeared as an unresponsive "zombie" bubble with no dismiss controls.
     - Root Cause 2: In Smore clippy.js, Agent.prototype._onQueueEmpty triggered idle animations (IdleRopePile, IdleAtom, etc.) whenever the speech queue finished typing. Many idle animations utilize internal frame branching loops that cycle indefinitely until exitAnimation() is called.
     - Root Cause 3: Clicking OK or Cancel previously only executed balloon hide(true) without canceling typing loops, stopping animations, or returning Clippy to neutral RestPose.
     - Resolution:
       - Patched Balloon.prototype.hide, Balloon.prototype._finishHideBalloon, and Balloon.prototype.close to explicitly set this._hidden = true, this._active = false, and clear this._loop and this._hiding.
       - Patched Balloon.prototype.show with an explicit guard: if (this._hidden) return.
       - Introduced dismissClippyBalloon(): immediately hides the balloon, clears and resets queue activity, calls exitAnimation(), and returns Clippy cleanly to RestPose.
       - Wired all OK, Cancel, and No action buttons to dismissClippyBalloon().
       - Patched Agent.prototype._onQueueEmpty: strictly prevents idle animations from playing while a speech balloon is visible on screen, and arms a 4.5-second safety exit timeout to guarantee idle animations never loop infinitely.
   - Intermediate 1.5x Medium Size Option:
     - Added "Medium Size" (scale 1.5) option between "Regular Size" (1x) and "Double Size" (2x) in the right-click context menu.
     - Implemented .clippy.clippy-medium-size with transform: scale(1.5) and transform-origin: top left !important.

   - 2px Teal Green Context Menu Outline & Theming:

18. Performance Optimization & 3D Element Rasterization Freeze Fix:
   - Root Cause Identification:
     - Investigated the up to 5-minute freeze during 3D element rasterization ('Rasterizing 3D Element...'), print rasterization, and 'Save as Picture'.
     - Identified that html2canvas 1.4.1 clones document.documentElement into an iframe sandbox before rendering any element.
     - The cloned document included over 83 off-canvas images (Unsplash thumbnails, DuckDuckGo proxy URLs, template previews, and hidden clipart galleries inside #dashboard-overlay, #template-modal, etc.).
     - In NW.js webview, unresolvable cross-origin requests and ORB-blocked proxy images left image load promises pending without firing load or error events, causing html2canvas's internal iframeLoader to wait up to Chromium's 300-second (5-minute) socket timeout.
   - Intelligent DOM Isolation Guardian (installHtml2CanvasOptimizer):
     - Injected an intelligent proxy wrapper around window.html2canvas:
       * Isolated Element Mode (3D shape rasterization, WordArt print masks, temp staging boxes): Filters out 100% of non-ancestor and non-descendant DOM nodes from the clone while preserving <head> stylesheets and fonts. Reduces cloned images from 83+ to 0 and cloned nodes to minimal essentials.
       * Full-Page Mode (Export and Booklet Print): Automatically ignores off-canvas dialogs, overlays, modals, and auxiliary toolbars (#dashboard-overlay, #template-modal, #splash-screen, #web-clipart-modal, #clippy-container, etc.), preventing hung off-screen resources from being requested in the clone.
       * Fast-Fail Image Timeouts: Caps imageTimeout to 2500ms (down from 15,000ms) to ensure slow network assets never stall processing.
     - Reduced 3D shape rasterization time from 300,000ms (5 minutes) down to ~180-260ms (over 1,000x faster).
   - Background Serialization & Observer De-confliction:
     - Main-Thread Contention Elimination: Marked window._rasterizingActive during rasterization passes to instruct _runDirtyCheck to bypass serializeCurrentPage() and JSON.stringify() while the 3D projection or print pipeline is executing.
     - Guarded serialization during modal interactions and throttled dirty check interval from 1500ms to 3000ms.
     - Disconnected suppressGuestSplash MutationObserver once #splash-screen is suppressed (with a 10s maximum watchdog), eliminating redundant DOM traversal on every canvas action.
     - Debounced the spellcheck enforcer MutationObserver (350ms delay) to prevent expensive querySelectorAll scans across the full document during heavy batch DOM operations.

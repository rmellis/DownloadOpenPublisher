# Recent Files Feature

## Overview
A native Recent Files button has been added to the Open Publisher desktop client, giving users quick one-click access to previously opened documents directly from the title bar.

## How it Works

### The Button
A compact **Recent Files** button with a clock icon and dropdown chevron sits in the top-right area of the native title bar, anchored to the left of the window controls. Its position remains identical whether Windows or macOS control themes are active. It is fully drag-safe (`-webkit-app-region: no-drag`) so it never interferes with window dragging. The button automatically hides when the window width is below **1120px** to prevent it overlapping the document title bar, and reappears when the window is expanded.

### The Dropdown
Clicking the button opens a styled dropdown panel showing your last opened documents. The panel features:
- A bold teal header labelled **Recent Documents** in a subtly deeper teal (`#00635e`) that gives depth against the application title bar
- A clean white list of files displaying the `Publication-icon-32x42.png` document icon on the left, with the filename prominently in bold and the full file path below it
- A matching deeper teal footer with a **Clear History** button to wipe the list
- A darker teal border (`#004d49`) that frames the panel clearly against the app background
- Hovering over an item highlights it with a soft teal tint
- The dropdown closes automatically when clicking anywhere outside it

### Persistence
Recent file paths are stored in `localStorage` under the key `op_recent_files`. The list is capped at a maximum of **10 entries**, with the most recently opened file always at the top. Duplicate entries are automatically de-duplicated and bumped to the top rather than added twice.

## Where Files Are Recorded
A file path is added to the Recent Files list at every possible entry point:
- Opened via **file association** (double-clicking a `.opub` file in Windows Explorer)
- Opened via the **in-app file picker**
- Saved for the **first time** via the Save As dialog (the new path is immediately recorded)
- Loaded by **clicking a Recent Files entry** (re-bumps it to the top of the list)

## Native Load Integration (Bug Fixes)
When a file is loaded via the Recent Files dropdown or file association, the wrapper delegates directly to the web app's native `handlePublisherFileLoad` function.

This ensures that loading a file from the desktop wrapper behaves exactly the same as opening it natively from the app's own "Open File" dialog. Specifically, it guarantees:
- **Perfect Orientation**: Populates the internal `window._orientedPagesRegistry` so the document immediately loads in its saved orientation (portrait/landscape) instead of defaulting.
- **Accurate Document State**: Restores `margins`, `rulerOrigin`, and `isSpreadMode`.
- **Thumbnail & History Sync**: Generates page thumbnails, resets the undo history stack, and toggles CMYK mode classes.
- **Protected Documents**: Properly triggers the native AES-GCM decryption flow if the file is password-protected.

## Status Bar Progress Indication
To provide immediate visual feedback when opening documents (especially larger publications):
- Clicking any document in the Recent Files list immediately lights up the bottom status bar with the soft green progress glow (`rgba(74, 222, 128, 0.45)`), identical to the desktop save animation.
- The status message updates to `"Loading Document..."` while the progress bar advances.
- Once rendered, the progress bar reaches 100%, displays `"Document Loaded!"`, and smoothly fades back to `"Ready"`.

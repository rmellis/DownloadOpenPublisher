# Update: Expanded Comprehensive Desktop Crash Logs

## Summary
The automated crash logs generated by the crashed and killed webview events have been significantly expanded. Instead of a basic 5-line output, the OpenPublisher-Crash-Log.txt now serves as a comprehensive diagnostic report, pulling detailed memory and environment states.

## Changes & Implementation Details
- **HUD Metric Extraction**: 
  - Dynamically rips the exact Webview RAM, Webview FPS, and DOM Nodes directly from the DOM UI elements (#dev-stat-ram, etc.) right before the renderer is terminated.
- **Node process Diagnostics**:
  - Pulls app uptime format (Xh Ym Zs) using process.uptime().
  - Captures exact wrapper memory boundaries (RSS and V8 Heap) using process.memoryUsage().
  - Dumps exact core dependencies via process.versions (NW.js, Chromium, Node.js).
- **Node os Diagnostics**:
  - Adds CPU topology (os.cpus()[0].model + core count).
  - Calculates total and free system hardware memory in Gigabytes.
  - Adds OS platform string and system architecture (os.arch()).
- **Application State**:
  - Exposes the exact absolute path of the ctiveFilePath being worked on.
  - Logs the window state (Fullscreen, Maximized, or Windowed) at the exact moment of failure.
